Ran from `shelfDashboard/` after a clean `npm install` (920 packages). Note: `package.json` requires
Node `>=24.0.0`; local environment is v22.19.0 — install/build/scans all still ran fine (`EBADENGINE`
warning only), but this is worth being aware of if anything behaves differently on a matching
Node version.

## `npm run lint` (`eslint .` only) — [exit 0]

- Raw output: `raw/eslint-output.txt`.
- **Important caveat, not a pass/fail on the tool itself**: this script does not run `tsc`. There
  is no `"typecheck"` script in `package.json` at all (confirmed: `grep '"typecheck"' package.json`
  → no match). `shelfPos`, by contrast, runs `npm run typecheck && npm run lint:eslint` under its
  `lint` script. This is the single biggest process gap found in this audit — see finding #1.

## `npx tsc --noEmit` (run manually — not part of any script) — [exit 2, 30 errors]

- Raw output: `raw/tsc-output.txt`.
- Trust level: **high** — this is the TypeScript compiler itself, using the project's own
  `tsconfig.json`, not a third-party heuristic tool.
- All 30 errors root-caused; see `02-findings.md` for the breakdown by cause. In short:
  - ~15 errors cascade from one `tsconfig.json` `lib` gap (`ES2022` vs. `toSorted` needing `ES2023`).
  - ~5 errors cascade from one route's search-schema becoming required without updating callers.
  - ~2 errors are a real union-narrowing gap in `reports.ts`.
  - ~2 errors are a real type hole in `OperatorStoresTable.tsx` bypassing an existing type guard.
  - Remainder are one-offs (unused reducer param, a Supabase SDK type mismatch).

## knip (`npx knip --reporter json`, no project-specific config — none exists) — [exit 1]

- Raw output: `raw/knip-full-scan.json`.
- No `knip.json` exists for this package (unlike `shelfPos`, which at least has one, even if
  incomplete). knip ran with its own auto-detection for a Vite + TanStack Start project.
- Exit code 1 here just reflects "issues found," not a crash (valid JSON was produced).
- Cross-checked against React Doctor's 4 warnings: **knip independently flags the same 4 items**
  (`print-lines-to-xlsx.ts` unused file, `billing.ts`'s `parseOptionalIsoDate`,
  `operator-auth-api.ts`'s `PRODUCTION_DASHBOARD_ORIGIN`, `signup-invite.ts`'s
  `buildOwnerSignupUrl`), plus a handful more knip-only findings (unused types in `reports.types.ts`
  and `types.ts`, unused devDependencies, two pairs of near-duplicate constant names in
  `src/lib/stores.ts`). Two independent tools agreeing is a much stronger signal than either alone
  — higher trust than the knip results in the `shelfPos` pass, where knip was the only tool and had
  a known config gap.
- **Unused devDependencies flagged**: `@tailwindcss/typography`, `@testing-library/dom`,
  `@testing-library/react`, `typescript-eslint` — not independently re-verified this pass (lower
  priority; devDependencies being "unused" per knip often just means "not imported in `src/`,"
  which is expected for test-only or config-referenced packages — check each before removing).
